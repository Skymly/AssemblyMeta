# 三方会议

代答人类决策的机制。主持人是主 agent，不投票。三位成员各是一个全新的只读子代理，同一份卷宗，互相看不见，并行出票。

## 何时开会

开会：

- `/grilling` 的 frontier 问题。一轮 frontier 合成一次会议，成员逐题作答。
- seam 确认（`/to-spec`、`/tdd`）、票的拆分与阻塞边（`/to-tickets` quiz）、`/triage` 的状态推荐。
- 1.0 级决定：特色功能准入、范围增减、公共契约取舍、文档语言策略、最低编译器版本、符号包与图标。
- 计划触及公共契约、新增 seam、或票面有真分歧的 Plan 批准。
- 自审里 MustFix 归类有争议，或回路卡住（[review](review.md)）。

不开会：

- 事实问题：派只读子代理去查，不投票。
- 票面、ADR、`CONTEXT.md` 已经回答的：直接引用。
- 不出票面范围、不碰公共契约的 Plan 批准：自批。
- 凭据、发布、人工点击：Blocked stop，会议无权代答。

## 卷宗

主持人写，成员只看这份：

1. 问题，逐题；每题至少两个选项，其中必有「不做 / 推迟」。
2. 主持人倾向（skill 给的推荐答案），标明「仅供参考，可被否决」。
3. 事实，子代理查来的，附出处。
4. 用户偏好：本次 `/goal` 原文、`CONTEXT.md`、全部 ADR、README「差异化」、`AGENTS.md`、`docs/agents/*`、既有 issue 里的取舍与「不纳入」。

## 三个席位

| 席位 | 代表 | 追问 |
|---|---|---|
| 使用者 | 项目维护者，以及从 ThisAssembly 迁过来、写 csproj 的开发者 | 用起来顺不顺？迁移成本多大？文档讲得清吗？对 1.0 的价值值不值一张票？ |
| 守门人 | 领域模型与架构 | 词汇是否守 `CONTEXT.md`？与 ADR 冲突吗？module 够深吗？seam 是否越少越好？1.0 契约以后还能演进吗？增量缓存与确定性、性能受影响吗？ |
| 质疑官 | 风险与范围 | 是不是 YAGNI？能不能更小？有没有抄上游？生成代码有无注入、路径穿越？最低编译器与 SDK 兼容吗？出错了能被测试发现吗？ |

## 出票

每位成员对每题返回：

- 选项编号。
- 依据：卷宗条目或可验证事实。没有依据的票作废。
- 附带条件（可空）。
- 否决（可空）。

## 否决权

成员只能因这几件事否决一个选项，主持人核实属实才生效：

- 与既有 ADR 冲突。
- 使用 `CONTEXT.md`「Avoid」里的词。
- 抄上游代码，或引入赞助检查、维护费、遥测一类机制。
- 触发发布或凭据动作。
- 让 [gate](gate.md) 里某一条不可能为真。

## 计票

1. 去掉被否决的选项。
2. 至少两票同一选项：采纳。
3. 三方各异：开第二轮，把三份票与理由给每位成员，各改票一次。仍各异，按序裁决：不违反 ADR 与 `CONTEXT.md` > 可逆 > 公共表面更小 > 风险更低 > 编号小者。
4. 少数意见照录。

## 落笔

- 决议评论到相关 issue，无票时评论到 map。首行 `> *This was generated by AI (three-party council).*`，内容：问题、选项、三票与依据、采纳项、少数意见。
- 难回头、无背景会让人意外、真有取舍，三条同时成立：用 `/domain-modeling` 写 ADR（编号接 0002 往后），新术语入 `CONTEXT.md`。
- 会议认为某条 ADR 或 `CONTEXT.md` 条目妨碍 1.0：不采纳冲突选项，把问题记入验收报告「请你复议」。

成员只读：不改文件，不碰 tracker。
