# 自审回路

每张实现票必过。审查对象是这张票相对 `base`（claim 时的 HEAD）的全部 diff。

## 回路

1. 提交当前实现（本票可以有多个提交）。
2. 并行派三个全新的只读子代理：
   - Standards 轴、Spec 轴：按 `/code-review`，固定点是 `base`。Spec 来源是票面、其 spec 父议题、相关会议决议。
   - 红线轴：逐条对照下面的 MustFix 清单。
3. 汇总成 MustFix / ShouldFix / Nit。每条带证据：`file:line` 加断言或复现命令；Spec 类再引用票面原句。**没有证据的 MustFix 降为 ShouldFix。**
4. MustFix > 0：全部修掉。先写一个能红的测试，再修成绿。重跑 `./eng/verify.ps1`，提交，回到第 2 步，换全新的子代理。
5. MustFix = 0，且这一轮审的就是当前 HEAD：通过。

Done when 最近一轮审查针对当前 HEAD，且 MustFix = 0。

## 限幅

- 同一条 MustFix（同文件同规则）第 3 次出现，或第 6 轮仍有 MustFix：开会（[council](council.md)）。议题三个：这是真 MustFix 吗？是方案错了要重做吗？要拆票吗？按决议再做至多 2 轮。
- 之后仍不为 0：Blocked stop。保留分支与 WIP 提交，票保持 claim，评论写明卡点。

## MustFix

1. 验收标准未满足，或行为错误。
2. 测试：新行为没有测试；断言同义反复，或绑在实现细节上；为求绿删改、放宽既有测试。
3. `./eng/verify.ps1` 不绿，有警告，新增 `NoWarn` 或 `#pragma warning disable`。
4. 词汇与决定：公共名称、文档、诊断文案出现 `CONTEXT.md`「Avoid」里的词；与 ADR 冲突。
5. 公共契约变动未登记：生成的成员形状、MSBuild 属性与元数据名、诊断码、包 ID、最低编译器版本。
6. 增量与确定性：生成器输入不是值相等；同一输入两次生成结果不同；生成物含时间戳、机器名、用户名、绝对路径；缺增量缓存测试或测试失败。
7. 正确与安全：字面量或标识符转义漏洞可注入代码；路径穿越；analyzer 里用了 `netstandard2.0` 之外的 API；生成器或任务因输入异常而崩溃，没有报诊断。
8. 清洁室：与上游源码逐段雷同；引入赞助检查、维护费一类机制；实现者读了上游源码。
9. 文档与行为不一致：`docs/使用说明.md`、README、包 README、诊断码表。
10. 范围：diff 里有与本票无关的行为改动。
11. 性能：性能票没有前后度量数据；非性能票引入了可测的退化。
12. 红线：密钥、发布动作、`main` 上的提交。

## ShouldFix 与 Nit

ShouldFix：可读性、命名、重复、过度抽象、没有度量的微优化。小且在范围内就修；否则写进票上评论的「Worth exploring」，供架构复扫读取，不自动开票。

Nit：风格，不处理。
