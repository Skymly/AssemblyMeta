### 公共契约

七个生成器都标了 `[Generator(LanguageNames.CSharp)]`，实现 `IIncrementalGenerator`。解析选项不是 C# 时直接返回，不写文件。载荷缺失时不写文件、不上报错误；载荷无法解码时上报 `AM0004`，也不写文件。源文件名与载荷键：

|---|---|---|---|

| Constants | `AssemblyMeta.Constants.g.cs` | `build_property.AssemblyMeta_ConstantsPayload` | `src/AssemblyMeta.Constants.Generator/ConstantsGenerator.cs` |
| Project | `AssemblyMeta.Project.g.cs` | `build_property.AssemblyMeta_ProjectPayload` | `src/AssemblyMeta.Project.Generator/ProjectGenerator.cs` |

共同形状来自 `src/AssemblyMeta.Core/Emit/CSharpSourceEmitter.cs`，并由测试断言：

- 文件头是 `// <auto-generated/>`、包名注释、`#nullable enable`、`#pragma warning disable`。
- 根类型是 `static partial class AssemblyMeta`。`AssemblyMetaVisibility` 为 `public` 时根类型是 `public`，空或 `internal` 时是 `internal`（`src/AssemblyMeta.Core/PayloadCodec.cs` 的 `MemberVisibilityParser`）。
- 嵌套类型一律 `public static partial class`。成员一律 `public`。
- 根类型为 `internal` 且类型在 `IdentifierSanitizer.IsConstEligible` 内时，成员是 `const`；否则是 `static readonly`。`public` 根类型把本可 `const` 的成员改成 `static readonly`。合格类型是 `bool`、`byte`、`sbyte`、`char`、`decimal`、`double`、`float`、`int`、`long`、`short`、`string`、`uint`、`ulong`、`ushort`，以及对应的 `System.*` 名（`float` 对应 `System.Single`）。`string` / `System.String` / `global::System.String` 视为字符串（`src/AssemblyMeta.Core/IdentifierSanitizer.cs`）。
- 点号变成嵌套类型。关键字加 `@`。命名空间无效则去掉 `namespace` 并报 `AM0005`。
- 含换行的字符串：语言版本号 `>= 1100` 时用 raw string（`"""`），否则转义（`src/AssemblyMeta.Core/Emit/CSharpLiteral.cs`）。`tests/AssemblyMeta.Generator.Tests/PayloadAndEmitterTests.cs` 的 `Multiline_string_uses_raw_literal_and_roundtrips`、`Older_language_version_does_not_emit_raw_strings` 分别用 C# 12 与 C# 10 断言这一点。`Public_visibility_uses_static_readonly_and_namespace` 断言 `namespace Demo.App` 与 `public static readonly string Version`。

各区成员：

- **AssemblyInfo**：`AssemblyMeta.Info` 下九个 `string`：`Configuration`、`Company`、`Title`、`Description`、`Product`、`Copyright`、`Version`、`InformationalVersion`、`FileVersion`。`Version` 的注释写明取 `AssemblyVersion`，不是 NuGet `Version`。`tests/AssemblyMeta.Generator.Tests/GeneratorTests.cs` 的 `AssemblyInfo_generator_emits_nine_constants` 断言这九个名字，并执行 `Version`、`Description`。
- **Constants**：`AssemblyMeta.Constants`。名字按点号嵌套，类型取 `Type`，空白则是 `string`。非字符串且 `Value` 为空则丢弃并报 `AM0003`。`Constants_generator_emits_nested_typed_members_and_duplicate_diagnostic` 断言 `public static partial class Http`、`public const int TimeoutSeconds = 30;`、`public const string @class = "keyword";`、raw string，以及重复名 `AM0001`。`FileConstant` 在编码阶段变成字符串常量：值是正斜杠相对路径，`Link` 优先于物理路径（`src/AssemblyMeta.Core/FileConstantNaming.cs`；`PayloadAndEmitterTests.cs` 的 `FileConstant_uses_forward_slashes_and_link`）。
- **Project**：`AssemblyMeta.Project`。成员类型固定为 `string`。无注释时摘要是「项目属性 {名}。」。`tests/AssemblyMeta.Generator.Tests/ProjectMetadataGitTests.cs` 的 `Project_generator_emits_nested_constants_and_cache_hits` 断言嵌套类、`public const string @class`、默认摘要「项目属性 Http.Timeout。」、`AM0001`，并执行 `Company` 与 `Http.Timeout`。
- **Metadata**：`AssemblyMeta.Metadata`。成员类型固定为 `string`。无注释时摘要是「程序集元数据 {名}。」。`Metadata_generator_emits_constants_and_cache_hits` 断言该类，并断言源码里没有 `AssemblyMetadataAttribute`，执行 `DemoKey` 与 `Area.Name`。
- **Git**：`AssemblyMeta.Git` 下五个 `string`：`Commit`、`Sha`、`Root`、`Url`、`Branch`。查询关闭时五个值是 `[pending build]`（`src/AssemblyMeta.Core/GitInformation.cs` 的 `PendingValue`），且不上报 `AM0006`。已查询但没有提交号时仍输出成员，并上报 `AM0006` 警告。`Git_generator_emits_members_pending_placeholder_and_cache_hits` 执行 `Commit`、`Sha`、`Branch`、占位 `Root`。`Public_git_uses_static_readonly_and_invalid_namespace_warns` 断言 `public static readonly string Commit`。
- **Resources**：路径段变成嵌套类。叶子有 `public static string Text`（私有字段 `_text` 缓存，经 `Manifest.ReadText`）、`public static byte[] GetBytes()`、`public static System.IO.Stream GetStream()`。至少有一条资源时才生成 `private static class Manifest`（`Open`、`ReadBytes`、`ReadText`）。空模型只有 `AssemblyMeta` 与 `Resources`，没有 `Manifest`（`Empty_resources_emit_the_class_without_the_reader`）。与外层类型、根上的 `Manifest`、叶子上的 `Text` / `GetBytes` / `GetStream` 同名时，标识符加 `_` 并报 `AM0008`。`Resources_generator_reads_manifest_and_renames_conflicts` 断言 `Resources_`、`readme`、`Text_`、`Manifest_`，并执行 `Text`、`GetBytes`、`GetStream`。
- **Strings**：`AssemblyMeta.Strings`。成员类型固定为 `string`。`{0}` 留在字面量里。与外层类型同名的片段改成带 `_` 的名字并报 `AM0008`。`Strings_generator_emits_constants_and_cache_hits` 断言 `public const string Greeting = "你好，{0}";`、`Strings_`、`AM0008`、`AM0001`，并执行 `Hello`、`Shopping.OutOfStock`、`Strings_`。`Public_strings_are_static_readonly` 断言 `public static readonly string Hello`，且没有 `const string Hello`。

`src/AssemblyMeta.Core/Emit/ISourceEmitter.cs` 的 `EmitterRegistry.Shared` 只注册 C#。`Registry_reserves_vb_and_fsharp` 覆盖 VB / F# 未注册。

### MSBuild 属性与元数据

七个包的 `buildTransitive` props 都把本包和元包 `AssemblyMeta` 的 `PackageReference` 更新为 `PrivateAssets="all"`。七个 targets 都把 `$(AssemblyMetaNamespace)`、`$(AssemblyMetaVisibility)` 传给编码任务。这两个属性在 props 里没有默认值。无法识别的可见性会打一条没有代码的 MSBuild 警告，并回退到 `internal`（`src/AssemblyMeta.Tasks/TaskSupport.cs`、`EncodeAssemblyInfo.cs`、`EncodeConstants.cs`）。

- **AssemblyInfo**（`src/AssemblyMeta.AssemblyInfo/buildTransitive/AssemblyMeta.AssemblyInfo.props`、`.targets`）
  - 编译器可见属性：`AssemblyMeta_AssemblyInfoPayload`。
  - 编译器可见元数据：项 `AssemblyAttribute`，元数据 `_Parameter1`。targets 没有把 `@(AssemblyAttribute)` 传给任务。
  - 目标 `AssemblyMetaPrepareAssemblyInfo` 读取并传入：`Configuration`、`Company`、`AssemblyTitle`、`Description`、`Product`、`Copyright`、`AssemblyVersion`、`InformationalVersion`、`FileVersion`。写出 `AssemblyMeta_AssemblyInfoPayload`。`DependsOnTargets="GetAssemblyAttributes"`。注释写了 `GenerateAssemblyInfo=false` 时仍依赖该目标；条件本身不读 `GenerateAssemblyInfo`。
- **Constants**（`src/AssemblyMeta.Constants/buildTransitive/AssemblyMeta.Constants.props`、`.targets`）
  - 编译器可见属性：`AssemblyMeta_ConstantsPayload`。
  - 项 `Constant`，元数据 `Value`、`Type`、`Comment`。
  - 项 `FileConstant`，元数据 `Value`、`Link`、`Comment`。
  - 目标 `AssemblyMetaPrepareConstants` 把 `@(Constant)`、`@(FileConstant)` 传给 `EncodeConstants`，写出 `AssemblyMeta_ConstantsPayload`。
  - `src/AssemblyMeta.Tasks/EncodeConstants.cs` 对 `FileConstant` 实际读取的是 `RelativeDir`、`Filename`、`Extension`、`Link`、`Comment`，不读该项的 `Value`。
- **Project**（`src/AssemblyMeta.Project/buildTransitive/AssemblyMeta.Project.props`、`.targets`）
  - 编译器可见属性：`AssemblyMeta_ProjectPayload`。
  - 项 `ProjectProperty`，元数据 `Value`、`Comment`。
  - props 默认加入的 `ProjectProperty`：`AssemblyName`、`RootNamespace`、`TargetFrameworkIdentifier`、`TargetFrameworkMoniker`、`TargetFrameworkVersion`、`RuntimeIdentifier`、`RuntimeIdentifiers`。
  - 目标 `AssemblyMetaPrepareProject` 在 `$(ProjectProperty)` 非空时把它按项加入 `ProjectProperty`，再按标识去重。写出的 `Value` 是同名属性 `$(%(...Identity))`，`Comment` 来自项元数据。写出 `AssemblyMeta_ProjectPayload`。
- **Metadata**（`src/AssemblyMeta.Metadata/buildTransitive/AssemblyMeta.Metadata.props`、`.targets`）
  - 编译器可见属性：`AssemblyMeta_MetadataPayload`。
  - 项 `AssemblyMetadata`，元数据 `Value`、`Comment`。targets 只把现有 `@(AssemblyMetadata)` 传给 `EncodeMetadata`，不在 props 里添加项。
  - 非跨目标（`IsCrossTargetingBuild` 不为 `true`）时 `DependsOnTargets` 为 `GetAssemblyAttributes`。写出 `AssemblyMeta_MetadataPayload`。
- **Git**（`src/AssemblyMeta.Git/buildTransitive/AssemblyMeta.Git.props`、`.targets`）
  - 编译器可见属性：`AssemblyMeta_GitPayload`。没有 `CompilerVisibleItemMetadata`。
  - props 在 `EnableSourceControlManagerQueries` 为空，且 `DesignTimeBuild` 或 `BuildingForLiveUnitTesting` 为 `true` 时，把 `EnableSourceControlManagerQueries` 设为 `false`。
  - 目标 `InitializeGitInformation` 读取：`EnableSourceControlManagerQueries`、`RepositoryCommit`、`RepositorySha`、`RepositoryRoot`、`RepositoryUrl`、`RepositoryBranch`、`SourceRevisionId`、`PrivateRepositoryUrl`、`PublishRepositoryUrl`、`SourceBranchName`、项 `SourceRoot`。`SourceControlInformationFeatureSupported` 为 `true` 时依赖 `InitializeSourceControlInformation`。
  - 同一目标把下列属性收进内部项 `_AssemblyMetaGitCi`：`GITHUB_REF`、`BUILD_SOURCEBRANCH`、`SYSTEM_PULLREQUEST_PULLREQUESTID`、`APPVEYOR_PULL_REQUEST_NUMBER`、`APPVEYOR_REPO_TAG_NAME`、`APPVEYOR_REPO_BRANCH`、`TEAMCITY_BUILD_BRANCH`、`TRAVIS_PULL_REQUEST`、`TRAVIS_BRANCH`、`CIRCLE_PR_NUMBER`、`CIRCLE_TAG`、`CIRCLE_BRANCH`、`CI_COMMIT_TAG`、`CI_MERGE_REQUEST_IID`、`CI_EXTERNAL_PULL_REQUEST_IID`、`CI_COMMIT_BRANCH`、`BUDDY_EXECUTION_PULL_REQUEST_NO`、`BUDDY_EXECUTION_TAG`、`BUDDY_EXECUTION_BRANCH`、`CHANGE_ID`、`GIT_LOCAL_BRANCH`。
  - 写出：`RepositoryCommit`、`RepositorySha`、`RepositoryRoot`、`RepositoryUrl`、`RepositoryBranch`。
  - 目标 `AssemblyMetaPrepareGit` 依赖 `InitializeGitInformation`，再写出 `AssemblyMeta_GitPayload`。
- **Resources**（`src/AssemblyMeta.Resources/buildTransitive/AssemblyMeta.Resources.props`、`.targets`）
  - 编译器可见属性：`AssemblyMeta_ResourcesPayload`。
  - 项 `EmbeddedResource`，元数据 `ManifestResourceName`、`LogicalName`、`Link`、`Comment`、`AssemblyMetaResource`。
  - 目标 `AssemblyMetaPrepareResources` 依赖 `PrepareResourceNames`，把 `@(EmbeddedResource)` 传给 `EncodeResources`。`IsCrossTargetingBuild` 为 `true` 时不运行。写出 `AssemblyMeta_ResourcesPayload`。
- **Strings**（`src/AssemblyMeta.Strings/buildTransitive/AssemblyMeta.Strings.props`、`.targets`）
  - 编译器可见属性：`AssemblyMeta_StringsPayload`。
  - 项 `EmbeddedResource`，元数据 `WithCulture`、`Culture`、`Link`、`AssemblyMetaStrings`。
  - 目标 `AssemblyMetaPrepareStrings` 依赖 `PrepareResourceNames`，传入 `$(MSBuildProjectDirectory)` 与 `@(EmbeddedResource)`。`IsCrossTargetingBuild` 为 `true` 时不运行。写出 `AssemblyMeta_StringsPayload`。

各 targets 里还有下划线前缀的任务程序集路径，以及 Project / Git 的内部项 `_AssemblyMetaProjectProperty`、`_AssemblyMetaResolvedProjectProperty`、`_AssemblyMetaGitCi`。

### 诊断码

生成器侧的严重级别由 `src/AssemblyMeta.Core/Emit/CSharpSourceEmitter.cs` 的 `Error` / `Warning` 决定，再经各生成器里的 `Diagnostics.Create` 映射。`AM0004` 的描述符写在七个生成器文件里，严重级别是 `DiagnosticSeverity.Error`，类别 `AssemblyMeta`。MSBuild 侧由 `src/AssemblyMeta.Tasks/TaskSupport.cs` 的 `LogCodeWarning` / `LogCodeError` 发出。

| 代码 | 严重级别 | 一句话 | 位置 |
|---|---|---|---|
| `AM0001` | 错误 | 常量或资源名与已有成员冲突，已忽略。标题是「常量名重复」或「资源名重复」。 | `CSharpSourceEmitter.cs` |
| `AM0002` | 错误 | 常量名或资源名为空，或某一段无法变成 C# 标识符，已忽略。 | `CSharpSourceEmitter.cs` |
| `AM0003` | 错误 | 类型不是 `string` 但 `Value` 为空，已忽略。 | `CSharpSourceEmitter.cs` |
| `AM0004` | 错误 | 无法解析编译期载荷。标题「AssemblyMeta 载荷无效」。 | 七个 `*Generator.cs` |
| `AM0005` | 警告 | `AssemblyMetaNamespace` 不是有效命名空间，已回退到全局命名空间。 | `CSharpSourceEmitter.cs` |
| `AM0006` | 警告 | 未能取得 Git 提交号。成员仍然输出。 | `CSharpSourceEmitter.cs` |
| `AM0007` | 警告 | 跳过 resx 里的非字符串项。 | `src/AssemblyMeta.Tasks/EncodeStrings.cs` |
| `AM0008` | 警告 | 名称与外层类型或生成成员冲突后已改写。Strings 的标题是「名称与外层类型冲突」，Resources 的标题是「资源名已调整」。 | `CSharpSourceEmitter.cs` |
| `AM0009` | 警告 | 嵌入资源没有清单名，已跳过。 | `src/AssemblyMeta.Tasks/EncodeResources.cs` |
| `AM0010` | 警告 | 嵌入资源无法映射为标识符；或 resx 在项目外且没有 `Link`；或 resx 键无效。已跳过。 | `EncodeResources.cs`、`EncodeStrings.cs` |
| `AM0011` | 错误 | resx 找不到、无法读取或无法解析。 | `EncodeStrings.cs` |

`AM0001` 到 `AM0011` 之外，可见性无法识别时还有一条没有代码的警告，见上一节。

## 五条工作流

### 对齐

要收成「已对齐」「超越」或「非目标」（带决议链接）。没有「缺失」「部分」。

缺失：

- 把常量挂到别的嵌套类型（`Root`）
- `{0}` 与具名占位符生成带参方法
- resx 键作为另一键的前缀时的诊断
- Vsix
- Prerequisites（1.2.11，2.1.6 已不依赖，不生成成员）
- 面向调用方的最低 MSBuild / Roslyn
- CI 预发布包版本

部分：

- 生成器只给直接引用的项目
- 命名空间属性名，以及非法命名空间时的诊断
- 可见性：public 时上游是 get-only 属性，本仓是 `static readonly`
- AssemblyInfo：文档中的九个名字对齐，上游还会收进其它程序集特性
- Constant：关键字转义、名字同时是成员和嵌套类型时的失败方式
- FileConstant：本仓把路径收成正斜杠
- AssemblyMetadata：本仓明确不收源码里手写的特性
- Git 设计时占位：本仓会把空的查询开关写成 false
- Git 分支与短哈希：本仓多认两种 PR 变量；短提交号原样当作 Sha
- SourceLink：缺信息时的诊断码不同
- 嵌入资源：本仓对每个纳入的资源都生成 `Text`
- 文本扩展名、`Kind`、`Comment`：本仓没有扩展名列表和 `Kind`
- 构建中追加嵌入资源：公开目标名不同
- resx：本仓是编译期常量，并认路径和点号
- 诊断码与触发条件
- 增量生成：本仓的缓存输入是单条载荷加语言版本；Constants 还没有增量缓存测试
- 包元数据：许可、标签、图标、符号包
- 文档形态
