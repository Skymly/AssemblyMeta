## 留给你的发布步骤

验收当时没有执行发布。后来改为 NuGet Trusted Publishing，不再用长期 API key，也不要把密钥写进仓库。

1. 把包含 `.github/workflows/release.yml` 的提交推上去。标签打在这颗或之后的提交上，工作流文件必须在被打标签的那颗提交里。
2. 标签必须是 `v` 加 `Directory.Build.props` 的 `AssemblyMetaPackageVersion`。先发预览就是 `v1.0.0-preview`。
3. `git push origin v1.0.0-preview`。推送者必须是 `Skymly` 或 `wys0610`；代理代推时认 `github.triggering_actor`。其他人推标签，`release.yml` 会失败而不是跳过。通过后跑 `./eng/verify.ps1`，用 OIDC 换短期密钥，先推七个子包再推元包，并用 `CHANGELOG.md` 的对应一节创建 GitHub Release。

nuget.org 策略 `Github-Action-Publish-AssemblyMeta` 只信任 `Skymly/AssemblyMeta` 的 `release.yml`。包主是 `Skym`，包名匹配 `AssemblyMeta*`。不要给发布 job 加 GitHub Environment。策略显示 7 天内要用一次，成功发布后才会永久生效。
